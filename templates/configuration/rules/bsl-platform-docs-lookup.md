# BSL: документация встроенного языка

Не выдумывай API, синтаксис конструкций, операторов и языка запросов платформы 1С. Перед использованием неизвестного имени или конструкции сделай lookup в MCP `bsl-language-server` и/или `1c-dev` `docs.*`. Это эвристики поиска, не справочник.

## Порядок выбора

1. **Текст запроса** (СКД / `Запрос.Текст`) → ветка «Язык запросов».
2. **Цикл / условие / попытка / объявление / директива / оператор выражения** → `docs.search` → `docs.get`. Не `global_member_search` и не `Глобальный контекст.*`.
3. **Метод / свойство / тип объекта** → ветка «API» (bsl-ls / глобал).

## API (глобалы и типы)

1. **Search → info/get.** Сначала кандидаты, потом одна карточка. Не вставляй в рассуждение весь JSON `global_member_search` (он часто огромный).
2. **Запрос.** Короткое русское имя, EN-алиас или короткий префикс. При нуле hits смени формулировку (EN / другой префикс / `docs.search`), не invent.
3. **Топ выдачи.** Бери 2–3 имени, не слепой top-1.
4. **Обзор семейства.** `docs.search` с `Глобальный контекст.<префикс>` (или имя/EN) → `docs.get`. Не голый «Глобальный контекст» и не тематические заголовки СП.
5. **Типы.** Члены объекта — `type_info` (после workspace bsl-ls). У примитива методов «как в ООП» может не быть — операции часто глобалы или операторы языка.

## Конструкции

- Семейство: `Оператор цикла`, `Оператор Если`, `Оператор Попытка` (или точное имя / EN). Не голое «Оператор» / «Операторы» — шум `*СхемыЗапроса*` и заглушки.
- Бери **голову** с описанием «Оператор …»; игнор хвостов «Часть конструкции…».
- EN: смотри `nameEn` в карточке. Не подставляй имена других языков вслепую (например `Break` ≠ `Прервать`).
- В карточке часто нет `examples` — скелет не invent; сверяй diagnostics / `analyze_file`.

## Операции выражений

- Точное имя или EN (`Новый`/`New`, `?`, `И`/`AND`, `ИЛИ`/`OR`, `НЕ`/`NOT`, `Выполнить`/`Execute`, `Ждать`/`Await`…).
- Арифметика `+ − * /`: карточки `Бинарные операции` / `Унарные операции` (в индексе могут быть `queryElement` — текст всё равно про операторы).
- Карточка `Логические операторы` — в основном **язык запросов**; для BSL не считать её единственным источником.

## Объявления, директивы, препроцессор, аннотации

- Имя без `#` / `&` или EN (`Процедура`/`Procedure`, `Асинх`/`Async`, `НаСервере`/`AtServer`, `Область`/`Region`, `Перед`/`Before`…).
- Омонимы (`Если` STATEMENT vs PREPROCESSOR): при `#…` — препроцессор; иначе — оператор модуля.

## Язык запросов

- Имя/EN или обзорные карточки вроде синтаксиса текста запросов / `ВЫБРАТЬ`.
- Одинаковые имена в BSL и в запросе (`НРег`, `Окр`…): для текста запроса — `queryElement`; для модуля — глобал / `method`.

## Антипаттерны и workspace

- Не искать оглавление / «Содержание» / тематические заголовки разделов СП — TOC через `docs.*` не отдаётся.
- Не invent после пустого или заглушечного hit.
- Не `global_member_search` для keyword-конструкций языка.
- После правок: diagnostics / `analyze_file` → снова lookup при unknown.
- Workspace bsl-ls: `list_workspace_folders`; нет корня — `register_workspace_folder` на корень IDE (не `src/cf`). Для platform lookup — `fileType=BSL`.
