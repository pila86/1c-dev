# Транзакции 1С

Транзакция используется, когда несколько операций с базой данных должны быть выполнены атомарно: либо успешно выполняются все операции, либо при ошибке изменения откатываются.

Не используй явную транзакцию без необходимости. При обычной записи объекта платформа сама выполняет запись в транзакции. Явно открывай транзакцию, когда требуется обеспечить атомарность нескольких операций или выполнить ответственное чтение данных.

## Структура транзакции

Начало, фиксация и отмена транзакции должны находиться в рамках одного метода.

Используй стандартную конструкцию:

```1c
НачатьТранзакцию();
Попытка

    // Все чтение, блокировки и изменение данных,
    // относящиеся к транзакции.

    ЗафиксироватьТранзакцию();
Исключение

    ОтменитьТранзакцию();

    // Дополнительная обработка ошибки.

    ВызватьИсключение;
КонецПопытки;
```

Соблюдай следующие правила:

* `НачатьТранзакцию()` вызывай непосредственно перед `Попытка`, вне блока `Попытка`.
* Все действия после `НачатьТранзакцию()` должны находиться внутри одного блока `Попытка`.
* `ЗафиксироватьТранзакцию()` должен быть последним действием в блоке `Попытка`, непосредственно перед `Исключение`.
* В блоке `Исключение` сначала вызывай `ОтменитьТранзакцию()`, и только после этого выполняй дополнительную обработку ошибки.
* При необходимости передавай исключение выше по стеку через `ВызватьИсключение`, особенно если метод может выполняться внутри внешней транзакции.
* В блоке `Исключение` после возникновения ошибки нельзя обращаться к базе данных, пока активная транзакция не отменена.

## Парность

Каждому `НачатьТранзакцию()` должен соответствовать `ЗафиксироватьТранзакцию()` или `ОтменитьТранзакцию()`.

Не открывай транзакцию в одном методе, а завершай её в другом:

```1c
// Плохо
Процедура ВыполнитьОперацию()

    НачатьТранзакцию();
    ЗаписатьДанные();

КонецПроцедуры
```

Открытие и завершение транзакции должны быть ответственностью одного метода.

## Вложенные транзакции

Не используй вложенные транзакции без веской причины.

В 1С нет независимых вложенных транзакций с возможностью отката только внутренней части операции. Повторный `НачатьТранзакцию()` увеличивает внутренний счётчик транзакций, но не создаёт отдельную транзакцию, которую можно независимо отменить.

Поэтому не добавляй `НачатьТранзакцию()` в методы, которые гарантированно вызываются уже внутри транзакции.

## Когда явная транзакция не нужна

Не открывай транзакцию только ради одной записи объекта или набора записей, если дополнительная атомарность не требуется.

Например, вместо:

```1c
НачатьТранзакцию();
Попытка

    Объект.Записать();

    ЗафиксироватьТранзакцию();
Исключение

    ОтменитьТранзакцию();
КонецПопытки;
```

предпочитай обычную запись:

```1c
Попытка
    Объект.Записать();
Исключение
    // Обработка ошибки.
КонецПопытки;
```

Платформа сама использует транзакцию при записи данных.

## Длительность транзакции

Транзакция должна быть как можно короче и содержать только действия, которые действительно должны выполняться атомарно.

Не выполняй внутри транзакции:

* длительные расчёты;
* лишние запросы;
* проверки, которые можно выполнить до начала транзакции;
* обращения к внешним ресурсам;
* HTTP-, SOAP-, FTP-сервисам;
* обращения к сетевым папкам и другим внешним системам.

Сложные расчёты и запросы, не требующие блокировки или ответственного чтения, по возможности выполняй до начала транзакции.

Для больших объёмов данных разбивай обработку на порции и фиксируй каждую порцию отдельной транзакцией, если это допускает бизнес-логика. Длительные транзакции удерживают ресурсы и блокировки и ухудшают параллельную работу пользователей. В стандарте ИТС в качестве ориентира для высоконагруженной системы приведён пример транзакции длительностью не более 20 секунд.

## Блокировки

Если для обеспечения целостности данных требуется блокировка, выполняй блокировку внутри той же транзакции, к которой она относится.

```1c
НачатьТранзакцию();
Попытка

    Блокировка = Новый БлокировкаДанных;
    // Настройка блокировки.
    Блокировка.Заблокировать();

    // Чтение и изменение данных.

    ЗафиксироватьТранзакцию();
Исключение

    ОтменитьТранзакцию();
    ВызватьИсключение;

КонецПопытки;
```

Не увеличивай область блокировки и продолжительность транзакции без необходимости.

## Общий принцип

Перед добавлением `НачатьТранзакцию()` сначала определи, какие конкретно операции должны быть атомарными.

Если атомарность нескольких операций не требуется — явную транзакцию не добавляй.

Если транзакция нужна — делай её минимальной по длительности и объёму выполняемых действий.
