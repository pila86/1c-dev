## Optional MCP: v8std

Если в сессии доступен MCP-сервер `v8std` — используй его для стандартов
разработки 1С. Если сервер недоступен — не выдумывай стандарты и не
притворяйся, что вызвал tool.

### Когда звать

- Вопросы «принято ли так в 1С», антипаттерны, стандарты оформления/архитектуры.
- Объяснение предупреждений стиля / стандартов со ссылкой на правило.
- Поиск стандарта по теме или номеру правила.

### Когда не звать

- Вместо `docs.*` / `bsl-language-server` для API платформы и синтаксиса.
- Вместо `metadata.*`, `build`, `check`, `test.*`, `debug.*` для работы с проектом.
- Не заменяет чтение текущего workspace и must-поток 1c-dev.

### Приоритет

v8std — SoT по корпусу стандартов. Локальные IDE rules (`bsl-module-structure` и др.)
дополняют проектные соглашения и не дублируют корпус стандартов.
